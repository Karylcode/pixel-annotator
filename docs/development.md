# Development

The app has no runtime dependencies and no build step: the browser loads `index.html`, `css/` and `js/` as
they are. Node.js and npm are only for the development checks (lint, regression checks, browser smoke tests).

## Setup

```bash
npm ci
npx playwright install chromium
```

## npm scripts

| Command | What it runs |
|---|---|
| `npm run lint` | ESLint 9 (flat config). Only the `no-undef` rule; `js/vendor/` is ignored. |
| `npm run check` | `node tools/check.js`. Plain Node, needs no npm packages. |
| `npm run test:e2e` | Playwright in Chromium. It starts `tools/static-server.js` on http://127.0.0.1:4173. |
| `npm test` | All three, in that order. |

`tools/check.js` covers:

- syntax of every `.js` file (`node --check`)
- the preset resolver, including the old names
- `legacy` output bit-identical to `tools/bench/baseline-legacy.json`
- the `pixel-perfecter` synthetic threshold (`--min-hit 13`)
- unknown presets fail instead of falling back to `legacy`
- the CLI default and aliases
- RLE and PNG round-trips
- clearing saved data (in-memory `localStorage` and IndexedDB)
- color normalization of the extra `parts` data
- every CSS and JS file referenced by `index.html` exists, and the worker loads the same algorithm files in the
  same order as `tools/pixelate-files.js`
- special image names such as `__proto__`

`tests/smoke.spec.js` covers drawing, undo, redo and JSON export; that the hidden labeling shortcuts leave the
data alone; that the labeling UI stays hidden on desktop and mobile layouts; special image names; turning the
labeling flag back on; and the warnings for mismatched `parts` data on import and on restore.

## CI

`.github/workflows/check.yml` runs on every push and pull request, on Ubuntu with Node 22: `npm ci`, lint,
`npm run check`, install Chromium, then the E2E tests. On failure it uploads `playwright-report/`.

## Benchmarks

**Synthetic cases** (24, generated by `tools/bench/gen.js`):

```bash
node tools/bench/run.js --method pixel-perfecter
```

| Option | Meaning |
|---|---|
| `--method <id>` | Preset or old name. Default `legacy`. An unknown name fails. |
| `--k <n>` | Color limit (default 0, no reduction) |
| `--bg` | Keep background removal on (the benchmark turns it off by default) |
| `--min-hit <n>` | Exit 1 when fewer than n cases are within ±1 cell |
| `--compare [file]` | Compare bit for bit with a baseline (default `tools/bench/baseline-legacy.json`) |
| `--baseline` | Rewrite `tools/bench/baseline-legacy.json` with this run |

Results and their limits are in [Pixelation methods](pixelation-methods.md#test-results).

**Real images**:

```bash
node tools/bench/images.js --dir <folder> [--methods a,b,c] [--only <part of a file name>]
```

It runs every preset on every PNG in the folder and prints the grid, reconstruction error, color count and
time. A few known file names are marked right or wrong. Always pass `--dir`; the built-in default is a folder on
the author's machine.

Keep test images out of git. `_testimg/` and `_out/` are already in `.gitignore`.

## CLI

```bash
node tools/pixelate-cli.js --preset pixel-perfecter in.png out.png
```

| Option | Meaning |
|---|---|
| `--preset <id>` | Preset or old name. Default `pixel-perfecter`. |
| `--k <n>` | Color limit. Default: the preset's own (48; 32 for `Image-to-Pixel`). |
| `--dither <id>` | `none`, `fs`, `bayer2`, `bayer4`, `ordered`, `clustered4` or `atkinson` |
| `--target-width <n>` | Output width for `PixelOE` and `Image-to-Pixel` |

- Input must be an 8-bit PNG (RGB, RGBA, greyscale or indexed). Plain Node, no npm packages.
- It prints `ok <w>×<h> grid=<nx>×<ny> <ms>ms preset=<id>` to stderr. It exits 2 when the file arguments are
  missing and 1 on any error, such as an unknown preset.
- This is the entry point for the official [pixel-bench](https://github.com/Retro-Diffusion/pixel-bench), which
  calls it as a subprocess. pixel-bench needs at least 50 native 1× pixel-art images of your own. The original
  suggestion is `_ref/bench-images/`, kept off GitHub; `_ref/` is not in `.gitignore` yet, so add it before you
  put images there.

## Deploying

GitHub Pages serves the `main` branch root (`.nojekyll` turns off Jekyll). Pages sends
`Cache-Control: max-age=600` for static files, so for 10 minutes after a deploy browsers can mix new HTML with
old CSS and JS. Before each deploy, run:

```bash
node tools/bump-assets.js [version]
```

It rewrites the `?v=` parameter on every local CSS and JS URL in `index.html` (default: the current time as
`YYYYMMDDHHmm`). The worker passes its own `?v=` on to the scripts it loads.

## Source layout

```
index.html               Layout
css/style.css            All styles (design tokens, light and dark themes, responsive layout)
js/codec.js              Data conversion: JSON/JS parsing, bitmaps, PNG upscale, SVG, ZIP
js/pixelate/             Pixelation pipeline: detect → arbitrate → sample → quantize → dither → clean
  lib/ grid.js index.js  Shared math, grid bounds, stage registry, presets, worker client
  detect/ sample/ quant/ dither/ clean/   One file per stage implementation
js/pixelate-worker.js    Background thread
js/vendor/               Image-to-Pixel dithering library (MIT)
js/store.js              State, undo stack, local saving
js/render.js             Canvas drawing
js/ui.js                 DOM and events (orchestrator)
js/ui/                   UI sub-controllers: overlays, export, persistence, pixelate-dialog, canvas-input
js/main.js               Entry point
tools/check.js           Check script (see above)
tools/pixelate-cli.js    Node CLI: PNG → pixelate → PNG (for pixel-bench)
tools/pixelate-files.js  Algorithm load list shared by the CLI, benchmarks and check script
tools/png.js             Minimal PNG reader and writer for Node
tools/static-server.js   Local static server for development and E2E tests
tools/bump-assets.js     Cache-busting for deploys
tools/bench/             Synthetic and real-image benchmarks, legacy baseline
tests/smoke.spec.js      Playwright smoke tests
```

Layering: `css` owns the look, `ui.js` owns the DOM and events, `render.js` owns drawing, and `store.js` owns
state. `codec.js` is pure data conversion. The `js/ui/` controllers must not call `PA.ui`. Files under
`js/pixelate/` run in the page, in the worker and in Node.

To add a stage implementation, register it with `PA.pixelate.register(stage, { id, label, run, … })`, then add
the file to `index.html`, `tools/pixelate-files.js` and the list in `js/pixelate-worker.js`, in the same order.
Presets live in `js/pixelate/index.js`.

## Hidden part labeling

Part labeling is hidden for now. `const annotationEnabled = false;` in `js/ui.js` is the only switch. The
`parts` data is still imported, saved, restored and exported, and the E2E tests check both settings.

## Design notes

Some choices that keep large images usable:

- **Sparse undo diffs**: a stroke records only the cells it actually changed. In the author's measurement, one
  long stroke on a 1500×1500 image took 74 KB instead of a 4.4 MB full copy. History has a memory budget per
  image (an estimated 192 MB across undo and redo, at most 60 steps), so it does not grow without limit.
- **Bitmaps in IndexedDB**: `localStorage` keeps metadata and RLE-compressed working data only, which avoids
  its quota of about 5 MB. Save data uses the key `pixann.v2`; data under the older `pixann` key is migrated on
  first start. When a save fails for lack of space, `pixann.v2.stale` records the time so the next restore can
  say the copy is older.
- Flood fill uses scanline fill, drawing merges same-colored rectangles into one `Path2D`, and redraws from
  pointer moves are merged into a single frame.
- `legacy` is kept, and its output is bit-identical to the version before the rewrite.
